## 1. 目标、边界与成功定义

### 1.1 需要解决的问题

| 编号 | 问题 | 成功定义 |
|---|---|---|
| G1 | 隔墙距离很近，但大回环需要长距离绕行，僵尸持续顶墙 | 原实体找到并走完需要先远离玩家的路线，路线不受当前 64～128 格单次搜索距离限制 |
| G2 | 僵尸与玩家存在较大高度差，免摔伤但不主动下落 | 在通道和落点可行时，原实体走出边缘、自然下落、实际落地并继续追击 |
| G3 | 原地往返、较大范围转圈或反复回到相同障碍 | 固定目标下的无效循环触发有效重规划；正常绕路、回头和追逐移动玩家不被误判 |
| G4 | 多怪、多房间下重复计算或抢占控制导致抖动 | 规划有公平调度和总预算，路线稳定，原生战斗与物种动作继续可用 |

到达率只统计同一实体真实完成的移动。传送、回收、重新出生、路径对象显示可达，都不能代替到达成功。

### 1.2 首期范围

- 覆盖当前房间地面导航支持的僵尸、尸壳、凋灵骷髅、苦力怕、狼、蠹虫、卫道士。
- 只对已安装导航控制器、并登记到对应房间的怪物启用新行为。实体种类符合白名单不等于已获得房间导航资格。
- 保留原生实体、`GroundPathNavigation`、`MoveControl`、攻击目标及物种动作；不引入 Mixin、反射、实体替换或全局导航替换。
- 唯一底层访问适配采用 addon 内单字段 Forge AccessTransformer，供 `NativeNavigationGuard` 取消托管阶段的原生延迟重算。它只改变字段可见性，行为写入限定于当前房间的托管实体；具体约束见 4.5.1。
- 保留现有出生合法性、波次预算、所有权登记和最终回收流程；必要的接口扩展必须有兼容测试。
- 在当前地图边界和已加载区块内规划，不主动加载区块、不修改地图地形、不要求地图数据迁移。
- 首期不新增飞行、游泳、攀墙、跑跳越沟或任意模组怪物的通行能力；已有特殊原生行为继续使用原生逻辑。
- 不通过扩大血量、改摔伤规则、无条件向玩家方向移动或强加速度来间接解决导航问题。

### 1.3 发布门槛

1. G1～G4 对应的实体行为测试全部通过。
2. 现有战斗、目标交接、出生、回收、房间清理和模块边界回归通过。
3. 8/32/64 怪及多房间负载报告齐全，明确记录失败、等待和回收，而不是只统计新增搜索次数。
4. 新实现默认启用之前，完成同一环境下的新旧实现对照；保留启动级旧实现回退开关。

## 2. 当前实现依据与改造落点

以下是源码检查结果，不是现场复现结论。具体地图中各因素的贡献，需要 P0 的测试和日志确认。

| 现有位置 | 已确认行为 | 改造要求 |
|---|---|---|
| `ZombiesGroundNavigationService.search()` | 扩搜节点目标为 1024/2048；搜索距离按直线距离加 32 并限制在 64～128；本地原生实现也用该参数限制累计路长 | 用房间连通关系决定全局探索；原生限制只用于适合它的短段 |
| `localCandidates()`、`nextLocalQuery()` | 8 方向、半径 2/4、每轮最多 12 次候选，耗尽恢复轮次后进入只探测模式 | 由有记忆的图搜索替代局部探点作为复杂地形的主要恢复方式 |
| `rememberBlockage()`、`refreshTerrain()` | 阻挡记录主要用于发现地形变化，没有直接成为下一次搜索的禁行连接 | 物理失败直接反馈到邻居生成和路径缓存 |
| `ObserverGoal.tick()`、`ZombiesNavigationProgressTracker` | 只在部分路径推进帧采样，主要检查 40 tick 窗口净位移比例 | 每 tick 采样，与路线进度授信分离；补充长期结构性进展 |
| `ZombiesMobSpawnService.spawnNext()` | 托管地面怪物不安装旧 `RoomMonsterDropDownChaseGoal` | 下落由统一路线执行器负责，不叠加旧的直接追人 Goal |
| `ZombiesEntityCombatEventAdapter.onEntityHurt()` | 房间所属怪物摔伤被取消 | 下落策略与实际免摔伤行为一致，不再依赖原生血量相关下落阈值 |
| `ZombiesNavigationGeometry.localTargetFeet()` | 只在上下 2 格寻找局部支撑 | 增加可分帧继续的深落点探测 |
| `ZombiesNavigationGeometry.checkSegment()` | 高度变化返回 `UNKNOWN`，避免错误的斜线平移判断 | 保留语义，新增动作专用验证，不能全部改成 `CLEAR` |
| `RoomSurvivorTargetGoal` 及共享选人函数 | 初选、保留、重选都可能使用原有距离条件 | 给已登记托管怪物统一接入房间目标资格谓词 |
| `ZombiesMap`、导航 reset 和生命周期处理 | 已有房间 tick、重置及服务器停止接入点 | 复用生命周期，避免新建脱离房间管理的永久静态状态 |
| 导航 GameTests / compat suite | 覆盖近处楼梯、墙体恢复、短周期振荡等；负载主要为上楼 | 补真实大回环、深下落、长周期循环和持续拥堵 |

建议新增实现包：`com.cdp.codpattern.app.zombies.service.navigation`。当前导航服务保留安装、目标、生命周期及调度门面，避免把所有职责继续堆入一个 Goal。

## 3. 总体结构与数据契约

### 3.1 职责划分

```text
ZombiesMap / MobSpawnService
  └─ 房间导航上下文、所有权、目标供应、生命周期
      └─ GroundNavigationService
          ├─ NavigationScheduler      分帧、公平队列、房间及服务器预算
          ├─ NavigationGraphCache     站立面、区域、入口、地形版本
          ├─ NavigationPlanner        分层搜索、结果状态、目标路线
          ├─ TraversalValidator       行走、跨步、精确移动、下落验证
          ├─ RouteExecutor            原生短路径、精确移动、下落、原生动作交接
          │   └─ NativeNavigationGuard 仅处理托管阶段原生延迟重算的覆盖
          └─ ProgressTracker          真实运动、路线进度、循环与等待时钟
```

这些名称表示拟新增或拆出的职责，不表示仓库当前已有相应类型。可以按职责拆文件，但不得合并规划结果与实体执行状态。

### 3.2 核心类型

| 类型 | 最少需要保存的信息 | 约束 |
|---|---|---|
| `NavigationContext` | 房间 ID、`ServerLevel`、地图边界、有效玩家供应器、生命周期标识 | 生产房间边界必须明确；所有世界读取在服务器主线程进行 |
| `MovementProfile` | 身体宽高、有效跨步能力、门交互能力、危险地形策略、房间下落策略、碰撞上下文类别 | 能力变化后旧路径和共享缓存重新验证；不同能力不得错误共享 |
| `SurfaceNode` | 分块位置、准确脚点/脚高、支撑面身份、净空及几何版本 | 同一 X/Z 不同楼层是不同节点，不能只用一个 `BlockPos` 代表所有支撑 |
| `TraversalEdge` | 有向起终点、动作类型、执行控制点、代价、依赖区域版本 | 一条边必须有可执行证据；下落不能自动生成反向边 |
| `RoutePlan` | 计划 ID、目标 UUID/目标站立区域、目标快照、区域版本、宏观入口序列、当前已细化路径 | 宏观计划与具体 `Path` 对象独立 |
| `RouteExecutionState` | 当前段/边、执行阶段、最后实质进展、原生让权状态、已提交下落 | 原生 Goal 暂停不能直接清空它 |
| `PlanningResult` | `READY`、`PENDING`、`WAITING_CHUNK`、`UNREACHABLE`，以及具体原因 | `PENDING` 必须细分 `BUILD`、`BUDGET`、`RESOURCE_LIMITED`；内存不足不是几何不可达 |
| `ProgressSnapshot` | 最后运动、最后路线推进、最后交战、特殊动作宽限、规划等待额度、循环证据 | 各时钟独立，重新规划不能伪造进展 |

动作类型固定为 `WALK`、`STEP`、`PRECISE_MOVE`、`DROP`、`NATIVE_INTERACTION`。`NATIVE_INTERACTION` 仅表达实体原本具备的交互能力，不借此新增破门或破坏方块能力。

### 3.3 最小服务接口

拟提供以下内部能力，按真实 Java 类型落地，不向网络协议或地图 JSON 暴露：

- `configureContext(context)`：绑定当前房间；同一运行实例重复绑定相同上下文应幂等。
- `requestPlan(mobId, start, target, profile)`：提交或复用规划请求，同实体只保留一个当前追击请求。
- `advance(serverTick, budget)`：推进排队任务；用服务器 tick 去重，不能按实体数量重复执行整份预算。
- `invalidate(bounds, reason)`：标记区域及依赖路线过期，不直接全图重建。
- `reportExecutionFailure(edge, evidence)`：区分静态碰撞、动态拥堵、目标变化和外力偏离。
- `cancelMob(mobId)` / `reset()`：释放请求、引用、队列条目和执行状态。

保留现有 `install()`、`resetNavigationRuntime()` 和指标读取入口；扩展它们的内部委托。旧构造函数可以保留，但真实生产房间必须显式绑定上下文；测试夹具提供明确测试边界，不以“无限世界”替代缺失边界。

## 4. 关键行为的确定方案

### 4.1 导航域与目标资格

1. 导航域取现有三维地图边界与世界建造高度的交集。支撑/相邻形状读取允许必要的只读外延，但实体站立点与通行轨迹不能借此走出地图。
2. 访问前检查所有涉及区块，包括碰撞形状可能读取的邻接区块；未加载时保持未知，不隐式加载。
3. 仅当怪物属于当前房间且已安装新导航时，使用房间级目标资格：供应器仍包含玩家、同世界/维度、存活且非旁观，玩家和怪物处于有效导航域。
4. 初始选人、保留当前目标、恢复时换人、执行时复核和回收服务的目标有效性，使用同一份托管资格判断。
5. 普通怪物和未托管物种保留原逻辑。不能仅修改 `supports(mob)` 或一个 `eligible()` 调用点就宣称完成。
6. 保留原生 `FOLLOW_RANGE` 的局部作用；托管宏观绕行不因瞬时超过 128 格而丢失合法房间目标。
7. 玩家离房、倒地导致供应器资格消失、死亡、切维度或越出导航域时取消后续追击；已提交下落先处理落稳。
8. 保留当前有效目标的稳定性，不因另一个玩家直线距离略近每 tick 切换。主目标确认不可达后，再通过图规划选择可达的房间玩家。

### 4.2 站立面、局部边与分层搜索

- 按 8×8×8 方块 tile 懒构建；从实际支撑形状提取候选脚高，并按身体大小检查支撑与净空。
- 原生格点作为基础候选。部分方块通道需要额外候选时，根据碰撞盒边界、身体半宽及统一几何 epsilon 生成位置，再做真实碰撞验证；不能只改方块类别白名单。
- 行走边检查整个身体扫掠、支撑连续性、危险地形和斜角净空；不能只验证两个端点。
- 跨步边按原生可执行的抬升和水平移动过程验证。无法证明时保留未知/受控执行状态，不把一次斜向 AABB 检查当作证明。
- 将 tile 内双向通行部分组织为区域，区域边界保留入口；下落和单向交互不得用于双向合并区域。
- 入口间细路径按需计算、缓存；区域层与细层都使用可暂停的搜索队列，保留 open set、已访问状态和重建信息。
- 未构建区域属于待展开边界，不能当作墙。未知连接保留在等待队列，tile 就绪后继续搜索或重新打开相关节点，不能从 frontier 中静默丢弃。尚有未知入口、未加载区块或被资源预算暂停的任务时，不能宣布 `UNREACHABLE`。
- 路线代价使用可执行距离及非负动作附加代价，启发式采用保守下界；无法证明下界时该部分使用零启发式。不能把较深下落设为零代价。
- 局部失败后优先修复受影响的路线部分；目标同一站立区域内小幅移动只更新末段，不重建整张图。
- 不承诺所有复杂地图都能在固定毫秒内完成冷启动搜索；容量和等待失败必须可诊断，不能伪装成地图不可达。

### 4.3 地形变化与失败记忆

| 事件 | 处理 |
|---|---|
| 身体实际撞到静态形状 | 记录有向失败边，撤销引用它的细路径和入口路径；下一次搜索直接排除该版本的边 |
| 怪物临时拥堵 | 个体短期等待/代价，初始冷却 20 tick；不污染共享静态图 |
| 方块、门、屏障形状改变 | 标记影响 tile 及必要邻接 tile；提升版本；旧边重新验证 |
| 区块卸载 | 挂起依赖请求、停止未提交的不安全移动；清除对世界对象的失效引用 |
| 没有接收到可靠事件 | 活动段执行前复核；失败区域按预算周期复查，发现形状变化后解除旧失败证据 |
| 玩家更换或移动 | 调整目标末段/规划上下文；不能把它记成静态地形失败 |

失败边键至少包含有向起终点、能力描述、所依赖的几何版本。不要只缓存终点，也不要永久封禁经过过的格子。动态碰撞形状受实体上下文影响时，不能仅靠方块状态 ID 共享结果。

### 4.4 下落探测与执行

**探测规则：**

1. 从可到达的平台边缘生成候选离边点；玩家正下方时也必须寻找真实平台边缘。
2. 向下扫描范围只受地图边界、世界高度和加载状态约束，不设置 16/32/64 格高度上限。
3. 扫描保存游标，预算耗尽后下一 tick 继续；复杂形状也必须可分批处理。
4. 检测实体会实际首先接触的表面。中途平台无法容身或危险时拒绝该候选，不能穿过平台选更低的落点。
5. 验证离边时的身体空间、下降通道、残余水平运动可覆盖的空间、落点支撑和净空。
6. 落点必须连通到后续追击路线，不能只因能站住就选择无出口坑。
7. 首期只实现走出边缘后自然下落，不把需要跑跳越沟的落点算成可执行 DROP。

| 执行阶段 | 行为 | 退出条件 |
|---|---|---|
| `APPROACH` | 通过已验证短路径靠近边缘内侧 | 真实到达起步区域，进入 `COMMIT`；路线失效则重规划 |
| `COMMIT` | 复核版本、当前身体及横向运动；停止原生导航，用 `MoveControl` 驱动到离边点 | 实际离地进入 `FALL`；仍在地面且通道失效则取消 |
| `FALL` | 原生重力与碰撞，水平控制限定到已验证落地区域，不跟随玩家每 tick 改方向 | 实际落地进入 `LAND`；外力或异常接触时重新定位 |
| `LAND` | 同时确认 `onGround()`、支撑面、净空和实际位置 | 成功则接下一段；提前落在其他平台则从实际位置重规划 |

执行不得使用瞬移、直接改 Y 速度或主动跳跃冲量替代下落。离边前的实际横向速度必须符合落地区域允许的漂移，不能只用一条竖直射线宣称安全。

已经离地的状态保存在服务中，不受 `!onGround()` 准入条件、20 tick 常规交接或 120 tick 恢复期限清除。目标失效只取消落地后的旧追击；房间结束仍由既有清理流程处理实体。正常下降属于动作进展，长时间悬空但没有真实下降则进入异常停滞处理。

### 4.5 原生短路径与控制权

1. `WALK/STEP` 使用规划器已验证的细节点构造短 `Path` 并交给现有导航器，不能再让 `createPath(portal)` 重新决定整段路线。缓存只保存不可变节点/边，每个实体单独创建可变 `Path`，禁止共享节点游标和可被裁剪的路径实例。
2. 整数节点不能表达的精确脚点由 `PRECISE_MOVE` 执行；使用同一套碰撞验证，停止会覆盖命令的原生导航。
3. 首版原生短段限制为相邻边或已验证的极短共线段，在 STEP、未经验证的拐角捷径、DROP 和交互边之前切段。`moveTo(Path)` 可能保留等价的旧路径对象，调用后读取 `getPath()` 检查实际路径，不能仅凭对象不相等判失控。原生跳节点、裁剪或自动重算后，对实际路径重新验证；不清宏观计划和失败历史。
4. 短段 `Path.canReach()` 仅表示段终点，不表示已恢复到最终玩家；`Path.isDone()` 也必须结合实际身体到达入口或支撑面才算段完成。撤销当前“完整路径走出两格即可清空全部恢复记忆”的宏观含义。
5. 地面常规执行达到 20 tick 后，在下一个安全短段边界安排原生调度机会；安全段应按短距离拆分，避免长直线路段无限延迟让权。
6. 让权窗口默认 4 个服务器 tick，至少覆盖一次原生 GoalSelector 调度。不要手动调用其他 Goal 的 `canUse()` 来试探，因为可能有副作用。
7. 真实特殊动作开始后允许完成；普通近战重算如果偏离规划走廊，则重新接管当前段。不能仅检查“已运行的特殊 Goal”，否则狼的跳扑可能永远没有启动机会。
8. 进入真实交战范围时交还原生攻击；保持视线、体型和物种规则。计划不能把持有 MOVE 的恢复 Goal 变成另一个攻击系统。
9. 交接前后重新确认目标资格。原生 Goal 的 `stop()` 清目标时，只能在原房间目标仍合法的前提下恢复关联，不恢复失效目标。

#### 4.5.1 原生延迟重算的最小适配

详细核查新增的实现约束：原生 `PathNavigation.tick()` 可以在 Goal 执行之后处理延迟重算；`stop()` 只清当前路径，公开的 `recomputePath()` 又存在节流，不能保证消除待重算标志。因此仅在 Goal 中检查一次路径，再假定本 tick 不会覆盖 DROP 指令是不成立的。

确定采用单字段 Forge AccessTransformer，不扩大为导航器替换：

```text
# 拟新增到 addon 的 META-INF/accesstransformer.cfg
public net.minecraft.world.entity.ai.navigation.PathNavigation f_26506_ # hasDelayedRecomputation
```

`f_26506_` 已按当前本地 1.20.1 映射核对，升级 Minecraft/映射版本时重新核对。实施时在 addon 的 ForgeGradle `minecraft` 配置注册该文件，并验证最终 JAR 中的运行时应用。只允许 `NativeNavigationGuard` 在源码中直接引用映射后的字段；AT 本身是全局公开该字段的可见性，不能声称 JVM 只对一个辅助类开放。

| 托管阶段 | Guard 操作 |
|---|---|
| 原生短 Path 的 FOLLOW | 每 tick 清除待重算标志，保留当前有效路径；不每 tick 调用 `stop()` |
| `PRECISE_MOVE`、`COMMIT`、`FALL` | 每 tick 停止原生导航、清除待重算标志，再发出当次经过验证的移动控制指令 |
| 原生让权窗口、特殊动作接管、非托管实体、旧引擎 | 不修改该字段；交还时不恢复已经取消的过时重算请求 |
| 已登记托管实体的目标相关区块缺失 | 暂停会读取缺块目标的原生攻击 Goal，并取消过时延迟重算，避免它主动加载区块；已经起跳的原生弹道和已提交下降继续自然落地，骑乘者不代理控制坐骑 |

Guard 由每 tick 执行的托管 Goal 调用，利用原生 GoalSelector → Navigation → MoveControl 的顺序生效。上表缺块行是发现原生强制加载入口后增加的安全接管条件，优先于正常的原生让权；只有相关区块确实缺失时适用。不要创建 `net.minecraft` 同包辅助类绕过访问限制，也不要把该访问扩展到其他原生私有状态。

专门增加回归：先制造待重算，再进入 FOLLOW/COMMIT/FALL，推进完整实体 tick，确认原来的玩家直线路径没有覆盖当前控制；交还原生控制后，原生重算依旧正常。开发环境通过之外，最终打包运行环境也必须验证 AT 生效。

### 4.6 进度、循环与回收

- 每 tick 采样一次真实位置；同 tick 多次调用覆盖同一槽位，保持有界内存。
- 短窗口沿用 40 tick，用于抖动和短往返检测；记录运动不等于刷新有效追击进度。
- 路线进度由实际沿当前细路径推进、跨过新入口、完成动作段及真实交战产生。不能单纯以更靠近玩家、换了 Path 对象、请求得到 CPU 时间或再次访问旧边刷新。
- 同时记录目标上下文、地图版本、宏观入口和有向边序列。固定目标下连续完成两次相同无收益闭环时触发循环恢复；第三次相同闭环不应继续作为正常追击执行。
- 非闭环的 ABAB 往返同样检测。判定时要求没有新的路线推进、出口探索或实质目标变化，避免封禁合理回头。
- 移动目标用累计移动和所在站立区域更新意图；不能以每 tick 坐标差或每次 replanning 重置历史。初始“实质移动”阈值为累计 2 格或目标进入不同站立区域，同时仍保留物理阻断边记忆。
- 启动时保留现有 320 tick 无有效进展、80 tick 扫描及最多两次重排的回收基线。
- 规划等待最多增加一次 320 tick 额度，只有真实路线推进或交战后可再次获得；新计划 ID、预算用尽、目标轻微移动均不能重复续期。
- `WAITING_CHUNK` 和 `PENDING` 不冒充进展。最终因等待耗尽回收时记录加载/容量/调度原因，不写入“地形永久不可达”，也不因此惩罚出生点。

### 4.7 预算与内存

下表是拟实施的首版默认值，不是实测性能结论。集中到内部 `NavigationTuning`，测试可注入更小预算；不新增地图规则字段。

| 项目 | 初始值/策略 |
|---|---|
| tile 大小 | 8×8×8 方块 |
| 新导航房间软预算 | 1 ms / server tick |
| 新导航服务器总软预算 | 4 ms / server tick；所有维度、所有房间合计 |
| 预算检查点 | 每个可暂停的节点展开、形状批次、扫描步之间 |
| 时间预算之外的工作计数上限 | 每房间每 tick 1024 次节点展开、256 次几何工作单元；达到任意上限即让出 |
| 全服计数上限 | 每 tick 4096 次节点展开、1024 次几何工作单元 |
| 单次公平调度片段 | 最多 64 次展开或 16 次几何工作单元，再轮转队列 |
| 图缓存上限 | 每房间跨所有 profile 合计 512 个 resident tile、65536 个站立节点、262144 条细边；任何一项先到即启动 LRU |
| 搜索状态上限 | 每房间合计 65536 个搜索记录；资源不足暂停新扩展并报告原因，不判不可达 |
| 个体循环历史 | 最多 256 个宏观入口/有向段记录；细边访问摘要随有效图版本维护并计入内存上限 |
| 失败区域周期复核 | 无预算竞争时每 40 tick 获得复核机会；活动下一段移动前必须复核 |

一个几何工作单元也不能隐藏对整条深井或整片地图的无界扫描；其内部按方块/碰撞盒批次检查时间并保存游标。第三方碰撞回调本身可能超过软预算，记录这类超时，不能声称 4 ms 是 JVM 或原生寻路的硬实时保证。

LRU 不驱逐正在执行的当前段、紧邻下一段及其落点证据，但不能无限钉住整趟长路线。远期细路径允许失效后重新细化；全部可用容量都被占用时暂停新任务并进入有界等待。宏观图、负缓存、open set、实体历史都要计入资源管理，不能只限制 tile 数。

世界访问全部在主线程；首版不引入异步世界读取。全服队列在服务器 tick 中统一轮转，房间 tick 只注册/更新请求，避免多个房间按固定顺序抢完预算。

### 7.3 性能验收

1. 分别运行 8、32、64 怪；另加 4 房间×32 怪的全服预算场景，每个场景至少 6000 tick，固定种子 1701/1702/1703。
2. 抵达后保留实体，继续移动玩家形成追击和拥堵；同时记录“不移除到达实体”的完成率，不能沿用上楼后立即 discard 的口径。
3. 冷缓存和热缓存分别统计，预热只排除时间分位统计，不删除冷启动到达/等待数据。
4. 所有工作计数预算零超额；软耗时超限记录具体单元和原因。不能把原生寻路或第三方碰撞回调耗时排除后宣称服务器成本受控。
5. 对旧实现本来可通过的对照负载，服务器 P95/P99 MSPT 的发布阈值分别为 `max(旧版对应分位 × 1.10, 旧版对应分位 + 2 ms)`。参考服务器新版 P95 同时不得超过 50 ms；若旧版环境本身已不满足该条件，先建立可比较的参考负载，不能用该机器声称性能通过。
6. 新增复杂场景要求功能通过、参考服务器 P95 ≤ 50 ms、无持续饥饿；报告实际 P99，不以旧版功能失败时的低计算量作为性能优势。
7. 新增缓存/队列计数不能随测试时长无界增长；房间结束后的逻辑引用计数归零。JVM 堆回收时机另行观察，不能要求瞬时 RSS 归零。

预算初值与性能阈值属于实施验收标准，尚未实测。若未通过，优先优化重复工作、缓存或调度；调整标准必须在报告中明确说明，不能默默提高预算后标记通过。

## 9. 发布、回退与风险处理

### 9.1 引擎选择

拟新增启动级系统属性：`codpattern.zombies.navigationEngine=legacy|layered`。

- P1～P5 开发期间默认 `legacy`；测试显式选择 `layered`。
- P6 全部通过后默认 `layered`；管理员可在下次启动选择 `legacy` 回退。
- `legacy` 指改造前当前房间导航实现，不等于纯原版 AI。
- 不做按 tick 自动来回切换引擎，不在异常时偷偷启用两套 Goal。
- 选择只在房间导航服务初始化时生效。无持久化导航图，不存在地图数据回滚迁移。

### 9.2 主要风险与处理

| 风险 | 必须采取的措施 |
|---|---|
| 碰撞形状随实体或邻块变化 | profile/上下文隔离、邻接区域失效、执行前复核；不只缓存 BlockState |
| 短 Path 被原生导航改写 | 验证实际执行路径，失效只重接当前段；保留宏观计划 |
| Goal 后的原生延迟重算覆盖下落 | 单字段 AT 与 Guard 明确取消托管期间的过时 pending；验证完整 tick 和最终打包环境 |
| 新 Goal 长期占 MOVE | 安全边界提供调度窗口；真实交战立即交还；保留狼跳扑回归 |
| 深下落水平漂移 | 验证实际离边运动及通道包络；落点不能仅凭竖直射线确定 |
| 全图冷构建成本过高 | 懒构建、游标续跑、公平队列、容量限制；不得启动时同步扫完整地图 |
| 等待额度造成怪物永久存活 | 等待独立时钟且只能有限续期；终端原因可观测 |
| 固定容量误判不可达 | 资源原因与几何结论分离；可回收但不污染地图/出生失败缓存 |
| 目标范围放宽影响普通怪物 | 安装状态与房间所有权双重约束；统一修改托管资格调用链 |
| 开门后旧失败记忆不释放 | 版本失效与周期复核；保留开门真实实体测试 |
| 通过回收或删断言掩盖失败 | 同 UUID 到达断言、回收单列、保留正常追逐反例 |

### 11.3 验证期间发现的边界修复

- 失效路线立即清除 `MoveControl` 的旧目标及移动输入；只调用导航器 `stop()` 不能停止此前的精确移动或离边命令。
- 目标变化改用相对上次实质目标位置的净位移。累计微小左右抖动或原地跳跃不再清空循环历史；1000 tick 微抖、100 次跳跃与真实移动两格的配对纯测试通过。
- 原生路径进展改用固定节点间的有向投影，避免换一份 `Path` 后从当前位置重新起算，使退后再回原终点冒充进步。新增同一路段退后 1.7 格再返回的纯反例已通过，第八轮日志确认静止阶段不再重复授信；剩余问题是确认不可达后的旧等待额度。
- 局部修复先从旧计划预算化复制仍有效的后缀，再从实际站立点寻找重接路线。仅此优化使用 256 次前缀展开额度；接不上、证据变更或资源不足均释放后缀并回退完整搜索，不把优化上限当作全局路径上限。复制、依赖复核、拼接和租约转移均计入原有预算，连续修复不保留历史计划链。纯检查证据：`round9-repair-pure/verification.json`。
- 房间所有候选目标均已确认不可达时结束本次计算等待额度；后续低频重查不能重新暴露旧宽限，只有真实进展或交战才能重新获得一次额度。主目标失败而仍有备用候选时，沿用原有限额度，不提前取消；新增纯反例和第九轮实体回收均通过。
- 冷规划期间原生调度窗口可能已经让实体沿路线前缀前进。取到计划时允许从附近的后续短段接入，最多检查 64 条边，仍对实际身体位置执行新鲜验证；不匹配时走预算化重规划。不会把 DROP 竖井中段当作新的离边位置。
- 测试记录到 `spawnNext` 成功但第 0 tick 世界实体查询仍为空、实体满血且没有移除原因。本地框架字节码显示结构准备只请求强制区块，未等待实体可见状态。公共实体夹具改用 20 tick 的 `setupTicks`，并在出生前断言区块实际为 entity-loaded 和 entity-ticking；行为测试自身的 500/600 等 tick 期限从第 0 tick 起保持原值。新旧当前实现使用同样准备条件；冻结 HEAD 测试保持原样并单独标识，不能将修改过的测试称为原始基线。
- 下落高度/血量矩阵与提前落地、外力变化使用独立测试命名空间。新增补测不会追溯标记为 P0 已冻结证据，也不修改既有常规回归的到达期限。
- READY 路线仍被控制器持有时继续计入房间和服务器的共享容量。搜索与执行各自保留租约，已提交下落不因搜索失效丢失计量；最后一个持有者释放后才归还配额。
- 路线重建阶段的依赖版本若被 LRU 逐出，会重新定位和证明，避免永远重试同一组已过期版本；不会以资源等待冒充几何不可达。
- 出生被 Forge 入世界事件拒绝时显式撤销已安装的导航控制器。未入世界实体的 `discard()` 没有正常的 level callback，不能依赖实体离开事件代为清理；独立生命周期测试检查失败后的预算、所有权和下一次出生。
- 服务器停止回调从只关闭规划器改为关闭整个房间导航运行时，解除控制器 Goal 并释放执行路线，再清理规划器和缓存；生命周期测试在实体仍活着时检查真实导航停止入口的释放结果。
- 房间导航 reset 后创建新的生命周期 UUID，使同一地图实例重开时不会复用已结束运行的身份；强制结束、删除及最终波次清理将通过真实地图服务入口验证。
- 独立长绕行参考曾在约 274 tick、40 格处被原生导航取消。本地 `PathNavigation` 字节码显示手工 `moveTo(Path)` 不重置跨节点累计的超时计数；参考驱动现在仅有界重发同一直线见证段的剩余 Path，并单独记录取消。没有调用被测规划器、没有扩大功能期限，也没有通过远端直接移动命令代替见证路线。
- 实际 Minecraft 1.20.1 字节码中，`GroundPathNavigation.canOpenDoors()` 调用的是 `NodeEvaluator.canPassDoors()`。能力签名、门几何和门夹具统一读取公开的 `getNodeEvaluator().canOpenDoors()`，保留实体原有 Goal 和权限，不给普通房间僵尸新增开门能力。
- 站立到达证明保存实际身体涉及的完整 tile 依赖，发布成功前分帧检查，完成后的依赖仍计入租约容量。缓存 revision 改变后重新进入预算队列，不能只检查脚点 tile；元数据版本被 LRU 淘汰时也提升 revision。真实半砖跨 tile 的头部碰撞变化补测和缓存证明复用补测已加入，规划纯检查新增版本淘汰反例，31 项通过。
- 输入路线的依赖也进入相同的逐批复核流程，避免在深井每个 tick 同步遍历完整依赖表。旧输入返回 `STALE` 并重规划，不记为碰撞失败；空中遇到 revision 改变先自然落稳，再从实际落点重算。已完成站立证明还检查实际位置，外力造成超过 0.2 格位移时重新验证，不因仍在到达容差内就复用旧身体证明。
- 区块补测区分 FULL 状态丢失和真正的 `ChunkEvent.Unload`。本地 `ChunkLevel`/`ChunkMap` 显示生成状态仍可能保留 LevelChunk；仅撤中间两列邻票不足以卸载。夹具延长至 256 格并移除远端票，使观察区块超过所有保留票的生成影响范围；保持 700 tick 卸载观测期限和 4000 tick 原实体到达期限。生产导航仍不申请或撤销区块票。
- 缺块保护在原生 Goal 的 `canUse()` 之前检查目标区块和可能读取的视线区块，全部使用非加载查询。它保留原生 Goal 对象及相对顺序，缺块时仍委托原控制器执行预算规划和已验证路线；不把安全绕行的 READY 改写为 WAIT。原生调度窗口另检查区块可用性，已提交下落保留至落地。三种真实区块模式已在第十五轮通过。
- 原生实体交替执行完整 GoalSelector 更新与仅 tickRunningGoals；后者不会询问新守卫的 canUse。每 tick 的既有观察 Goal 因此前置，在缺块时先停止可能读远端地形的原生 Melee/Bow，恢复仍合法的同一目标，再按原有有限等待和托管路线执行。仅 layered 房间的 TARGET Goal 也前置，避免首次原生目标筛选抢先读取视线区块。第三变体先让真实原生弓攻击运行，再严格选择下一次半频实体更新前移动玩家到已卸载区域；不移动怪物、不手动执行 Goal，仍要求等待后原 UUID 实际近身抵达，第十五轮已通过。
- 第十一轮固定目标轨迹还观察到约 2 格的自然往返，循环信号出现后进度时钟没有续期，最终在 880 tick 真实回收。这可以支持短往返场景；大环有序入口仍未闭合，不能替代 N08 所需的自然 80/240 tick 大闭环复现。相应纯历史反例通过与实际大闭环未复现分别记录。
- 新增复杂实体场景使用共享服务器时钟补充 `complex-mspt.json`：从 Forge START HIGHEST 到 END LOWEST，包含完成当帧的 END 调度，不排除冷启动。固定场景清单决定哪些项目执行 P95 ≤ 50 ms 门槛；原有兼容场景只观测，P99 如实报告。空样本、缺帧、调度覆盖不足、未完成或功能失败不能通过。实际 Minecraft 在 START 后递增 tickCount，严格按原始 START 计数 + 1 对应 END 计数；只读时钟不创建导航调度器。第十五轮主回归的全部窗口已核验；测试扩展已停止，收尾复用这些证据。

## 12. 运行与可选复验说明

### 12.1 选择引擎

当前默认使用 `layered`，无需额外启动参数；Gradle 导航测试和报告也使用相同默认值。需要显式指定时，在服务端 Java 启动参数（`-jar` 或参数文件之前）添加：

```text
-Dcodpattern.zombies.navigationEngine=layered
```

重启时改为 `-Dcodpattern.zombies.navigationEngine=legacy` 即可回退。选择在房间服务初始化时读取，不支持实体追击中途热切换。无需地图路点、地图 JSON 迁移或新的客户端协议。

只有真实房间登记、已安装控制器的支持物种使用分层导航；地图边界由房间实例注入。未加载区块保持等待，不主动加载。规划等待有期限，资源不足与几何不可达分别记录。

开发诊断可添加 `-Dcodpattern.zombies.navigationDebug=true`，输出房间、原实体 UUID、目标、坐标、执行阶段、当前边、规划状态和缓存统计。持续负载对照省略 debug 参数，以免把大量日志开销混入比较。

默认合成环境为原生难度 `easy`；它与僵尸模式波次规则不同。启动报告分别记录预期难度和实际 `ServerLevel` 难度。区块补测只在它自己的隔离世界中撤销并恢复测试票和出生区票，生产导航不添加区块票。

`-PnavigationChunks -PnavigationChunkStartsMissing` 在独立进程中运行初始缺块变体：先观察真实卸载，再创建第一个房间实体，检查出生及首次原生 Goal 调度不会加载目标区块。该附加属性不能用于其他测试组。

`-PnavigationChunks -PnavigationChunkTargetMovesMissing` 运行已有原生弓攻击的半频更新变体：玩家从近端已加载位置移到实际缺块位置，再等待并恢复。两个区块附加属性互斥，均只用于独立区块测试进程。

`-PnavigationReference` 是独立的已知路线移动校准，用例会主动发出移动命令，其结果不能算作规划器的功能通过证据。当前补测发生于实现之后，不能补造“改造前测得参考耗时”的时间顺序。

每轮报告至少检查 `launch-environment.json`、`compiled-addon-classes.sha256`、`run-summary.json` 与实体场景 JSON。测试任务会检查实际命名空间、执行数量和失败数；编译成功或只有 `testClasses` 成功都不等于行为测试通过。JFR 脚本 `scripts/navigation-jfr-summary.py` 提供采样栈与 GC 摘要，采样中未出现原生寻路栈不等于其耗时为零。

# 僵尸模式武器卡片：对照 zom.svg 的分析与改进方案

日期：2026-09-22。代码基线：`55fe6c5`。

当前优化稿：[zom.svg](zom.svg)。未修改的原稿备份：[zom-original.svg](zom-original.svg)，与桌面源文件逐字节一致。HUD 局部渲染预览：[zom-hud-preview.png](zom-hud-preview.png)。

第 2、4、5 节保留原稿测量与布局推导，便于对照；第 8 节记录 SVG 的小幅优化；第 9 节记录游戏代码的紧凑适配，以第 9 节为当前实现口径。背景画布保留用于展示，不计入游戏 HUD。

本文只分析 SVG 的武器 HUD，忽略整个 1024×768 画布的黑色、白色和灰色背景，也不采用原稿在画布中央的位置。游戏内继续使用右下角锚点。**字体暂时不管**：沿用当前 Minecraft 字体，不引入字体文件、数字贴图或字形重绘；字号比例、对齐和间距属于本次布局分析。

核对补充：**卡片宽高比是构图基准，允许为显示适配微量调整；弹匣与备弹数字的大小关系是重点，应联动保持。** 优先顺序为：信息可读且不重叠 → 数字大小层级 → 主要元素位置关系 → 外框比例和留白精确度。

本文包含最初的实现方案及后续代码落地记录。第 1–7 节中的“当前代码”指最初基线；新的实现见第 9 节。未启动客户端进行实机截图验证；原稿及优化 SVG 已使用本地 SVG 渲染器核对局部画面。

## 1. 结论

现有卡片已经具备参考图的全部核心数据：当前枪械轮廓、稀有度、升级罗马数字、弹匣弹药、备弹和射击模式。改造重点是渲染与布局，不需要为了这张参考图新增服务端协议。

优先处理以下差异：

1. 把稀有度底色改为左浓右淡的低透明度横向渐变；目前实际是上浓下淡，且颜色明显更实。
2. 以 SVG 的 `586×153` 为卡片比例基准，重新分配枪图、弹药及右侧留白；允许为像素取整、可读性和显示空间微调宽高。
3. 联动放大弹匣与备弹数字，保持约 `8:3` 的可见高度比；放大并固定射击模式图标，形成清楚的上下两行。
4. 左侧竖条使用中性浅灰色，升级等级下移，枪械贴图不再统一降到 80% 不透明度。
5. 统一卡片“确实可绘制”的判断与 TaCZ HUD 隐藏条件，补上小屏和超长数字的边界处理。

## 2. 原稿备份的 HUD 规格

有效 HUD 范围为 `(226,307)` 到 `(812,460)`，宽 `586`、高 `153`，宽高比约 `3.830:1`。下面把该区域左上角当作 `(0,0)`，避免把画布留白带进游戏布局。

| 元素 | HUD 内相对位置与大小 | 外观 / 含义 |
| --- | --- | --- |
| 稀有度色层 | `(0,0)`，`586×153` | 从 `#A200FF` 向右渐隐 |
| 左侧竖条 | `(0,0)`，`5×153` | `#D9D9D9`，不透明度 80%，不是紫色 |
| 枪械图片框 | `(0,13)`，`384×128` | 内嵌 `hk416a5.png`，3:1，透明背景 |
| 弹匣 `030` | 约 `(386.88,29.80)`，`159.12×67.20` | 白色，不透明度 80% |
| 备弹 `0120` | 约 `(474.08,104.80)`，`73.14×25.20` | 白色，不透明度 80%，与弹匣近似右对齐 |
| 升级 `II` | 约 `(17.92,123.85)`，`14.17×23.15` | 白色，不透明度 100%，位于左下角 |
| 射击模式图片框 | `(384,97)`，`43×43` | 内嵌 `fire_mode_auto.png`，不透明度未额外降低 |

数字与等级的尺寸是矢量字形的可见范围，不能直接等同于 Minecraft 字体的行高。枪图和模式图标的尺寸是图片框范围，素材自身还有透明边缘，不应裁掉后直接套用同一组位置。

### 数字大小比例：按可见高度核对

| 关系 | SVG 实测 | 布局含义 |
| --- | --- | --- |
| 弹匣 / 备弹高度 | `67.2 / 25.2 = 8/3 ≈ 2.667` | 弹匣是备弹的约 2.67 倍高，是数字层级的主要约束 |
| 备弹 / 弹匣高度 | `0.375` | 确定弹匣大小后，备弹高度取其 37.5% |
| 升级 / 备弹高度 | `23.148 / 25.2 ≈ 0.919` | 升级数字略小于备弹，不能与弹匣同等突出 |
| 弹匣 / 卡片高度 | `67.2 / 153 ≈ 43.9%` | 确定数字整体在卡片中的视觉占比 |
| 备弹 / 卡片高度 | `25.2 / 153 ≈ 16.5%` | 卡片微调时可小幅浮动，优先保留弹匣 / 备弹比例 |

`030` 与 `0120` 的整串宽度比约为 `159.12 / 73.14 ≈ 2.176`，这受到字符数量和字形宽度影响，**不能把它当作字号比例**。暂不更换字体时，不要求整串宽度复制 SVG。

### 透明度和图层顺序

稀有度路径设置了 `fill-opacity="0.2"`，左侧渐变 stop 又设置了 `stop-opacity="0.8"`，因此最左侧实际不透明度为：

```text
0.2 × 0.8 = 0.16 ≈ 41 / 255
```

不是 80%，也不是单独的 20%。右端不透明度为 0。

原稿顺序是：枪图 → 稀有度渐变 → 弹匣 / 备弹 / 等级 → 射击模式图标 → 左侧竖条。因此枪图会受到一层很淡的稀有度着色。建议首次实现沿用这个顺序；竖条最后画，保持边界干净。

这里“忽略背景”指忽略整张画布的背景矩形；这层表达稀有度的渐变是 HUD 自身的一部分，应保留。

## 3. 当前代码已经做了什么

主要入口是 [ZombiesHudOverlay.java](../src/main/java/com/cdp/codpattern/client/gui/overlay/zombies/ZombiesHudOverlay.java)：

| 位置（基线行号） | 职责 |
| --- | --- |
| 第 95–124 行 | 卡片尺寸、布局、文字透明度、TaCZ 模式图标资源 |
| `renderHeldWeaponPanel()`，第 948 行起 | 定位卡片，绘制渐变、枪图、等级、弹药、模式图标 |
| `heldWeaponPanelData()`，第 1081 行起 | 校验持枪与房间，读取实时弹药、稀有度、升级、模式和贴图 |
| `upgradeRoman()` / `formatAmmo()` | 罗马数字和补零格式化 |
| `shouldReplaceTaczGunHud()`，第 940 行起 | 决定是否隐藏原 TaCZ 枪械 HUD |

现有数据可以继续复用：

- 弹匣来自 `IGun.getCurrentAmmoCount(stack)`，备弹来自 `TaczClientApi.resolveReserveAmmo(stack)`，不应改为读取可能过期的初始备弹标签。
- 枪械轮廓来自 `TaczClientApi.getGunHudTexture(stack)`，随当前武器变化；`null` 时已有物品图标回退。
- 模式来自 `IGun.getMainHandFireMode(...)`，已有半自动、全自动、连发三种 TaCZ 图标映射。
- 稀有度来自 `TAG_RARITY_ID`；[ZombiesRarityDisplay.java](../src/main/java/com/cdp/codpattern/client/zombies/ZombiesRarityDisplay.java) 已提供普通绿、稀有蓝、史诗紫、传奇橙。
- 左下角罗马数字来自 `TAG_UPGRADE_LEVEL`。它代表升级等级，不是 `TAG_WEAPON_LEVEL`；零级不显示。
- 弹匣最少三位、备弹最少四位，超出位数不会截断；已有低弹量变红逻辑。

主模组中的 `GuiTextHelper.referenceScale()` 返回 `2 / 当前 GUI scale`。当前卡片尺寸会乘这个比例，而右、下边距各 12 是 GUI 坐标值。因此 `320` 是布局参考宽度，不等于固定 320 个物理像素；空间充足时，GUI scale 为 2 的卡片约宽 640 个物理像素。以下尺寸比较全部在参考布局坐标中进行。

## 4. 当前实现与 SVG 的差异

| 项目 | 当前实现 | 改进方向 |
| --- | --- | --- |
| 卡片比例 | `320×90`，约 `3.556:1` | 以 `320×83.55`、约 `3.830:1` 为起点，允许适配微调 |
| 枪图 | `(12,11)`，`196×66` | 约 `(0,7.10)`，`209.69×69.90`，更靠左、更大 |
| 渐变方向 | 调用 `GuiGraphics.fillGradient()`，实际纵向渐变 | 明确实现横向渐变 |
| 渐变强度 | 起点 alpha 204，约 80% | 起点 alpha 41，约 16%，终点 0 |
| 左侧竖条 | 宽 2，使用稀有度颜色 | 宽约 2.73，浅灰色、80% 不透明度 |
| 枪图透明度 | 用 shader 统一乘 0.8 | 使用素材自身 alpha，再叠加淡色渐变 |
| 弹匣大小 | 当前字体放大 `2.25` 倍 | 目标可见高度约 36.70，作为数字组主尺度，右对齐 |
| 备弹大小 | 当前字体缩放 `0.86` 倍 | 目标可见高度约 13.76，与弹匣联动保持 `3:8`，宽度按现有字体适配 |
| 弹药右边距 | 10 | 约 21–22，保留原稿的右侧留白 |
| 模式图标 | `10×10`，X 位置依赖弹匣字符串宽度 | 约 `23.48×23.48`，固定在下行左侧 |
| 升级数字 | X=12，Y 由底部 11 和字体行高倒推；80% 不透明度 | X 约 9.79，更贴近左下角，白色 100% |
| 图层顺序 | 渐变先于枪图 | 按 SVG，把淡色渐变叠在枪图后面绘制 |

若按默认 `font.lineHeight=9` 估算，当前弹匣与备弹的行高只有约 `20.25` 与 `7.74`；即使暂不更换字体，数字在卡片中的占比仍需要提高。这里行高与 SVG 可见字形高度并非完全相同，实际落地需要按现有字体度量校准。

当前两个字号之比为 `2.25 / 0.86 ≈ 2.616`，比目标 `2.667` 低约 1.9%，**相对大小已经接近参考图，主要差距是整体偏小和摆放位置**。不能把备弹单独放大到与弹匣接近，也不能为塞进原稿宽度而单独压小备弹。升级的当前缩放为 1，和备弹的 0.86 相比字号参数更大；参考图则是升级略小于备弹，需按各自实际字形可见高度校准。

### 渐变方向是实现问题

已检查本地 Forge `1.20.1-47.4.0` 映射依赖中的 `GuiGraphics.fillGradient` 字节码：顶部两个顶点使用第一个颜色，底部两个顶点使用第二个颜色，确实是纵向渐变。

现有静态测试虽然写着“left-to-right”，实际仅检查源码包含 `graphics.fillGradient(`，无法证明渐变方向正确。后续不能继续把“调用了这个方法”作为横向渐变的验收依据。

### 弹药与模式图标的布局应解耦

当前图标的 X 坐标由 `currentX - iconSize - gap` 得出，数字变长时图标会横向移动。参考图中图标占据固定的下行左侧区域，备弹占据下行右侧区域。两者各自锚定后，弹药变化不会带动图标跳动。

`Math.max(ammoLeft, currentX)` 仅能防止数字越过左边界，不能保证长数字不越过右边界。现有格式化支持四位以上弹匣和五位以上备弹，布局也必须支持。

## 5. 推荐的布局方案

### 使用 SVG 局部坐标作为基准，允许外框微调

保留 `586×153` 的设计坐标作为默认构图，统一映射到游戏卡片。这样尺寸、偏移和留白都能追溯到原稿。它不是必须逐像素复刻的硬边框：例如参考宽度为 320 时，可从高 83.55 取整到 84，或按行间距需要小幅增加到 86。这些是适配示例，不是已经实机确定的最终尺寸。

```text
designWidth  = 586
designHeight = 153
referenceWidth  = 320
referenceHeight = referenceWidth × 153 / 586 ≈ 83.55
panelWidth   = referenceWidth  + widthAdjustment
panelHeight  = referenceHeight + heightAdjustment

layoutScale  = min(referenceScale, availableWidth / panelWidth,
                   availableHeight / panelHeight)
designScale  = referenceWidth / designWidth × layoutScale

screenX = panelLeft + designX × designScale + anchorOffsetX × layoutScale
screenY = panelTop  + designY × designScale + anchorOffsetY × layoutScale
```

默认 adjustment 和 anchorOffset 都为 0。外框微调时，通过锚点偏移和间距吸收差额：右对齐的数字组随右边界移动，左下等级随下边界移动，枪图按需要微调位置；背景和竖条覆盖调整后的完整高度。枪图、数字和模式图标仍各自等比绘制，不能对整个内容施加不等比拉伸。上下两行之间的净间距优先保留，避免只移动备弹却挤压其他元素。

如果保留 `320×90`，相对基准高度已增加约 7.7%，不能默认称为单纯取整；应有显示适配依据，并重新检查数字占比和留白。外框微调应服务于阅读，不应掩盖数字过小的问题。

`availableWidth`、`availableHeight` 扣除边距，并按实际需要扣除其他 HUD 的占用。首版保持右下各 12 GUI 单位的现有定位习惯；不照搬 SVG 在整张画布中的居中位置。最后绘制时统一取整，避免分别取整带来的缝隙。

在 `layoutScale=1`、没有外框微调时，下列值是参考构图。文字宽度是 SVG 样例字形的测量结果，不是当前字体必须塞入的硬限制：

| 区域 | X | Y | 宽 | 高 |
| --- | ---: | ---: | ---: | ---: |
| 卡片 | 0 | 0 | 320 | 83.55 |
| 左竖条 | 0 | 0 | 2.73 | 83.55 |
| 枪图框 | 0 | 7.10 | 209.69 | 69.90 |
| 弹匣可见目标框 | 211.27 | 16.27 | 86.89 | 36.70 |
| 备弹可见目标框 | 258.88 | 57.23 | 39.94 | 13.76 |
| 模式图标框 | 209.69 | 52.97 | 23.48 | 23.48 |
| 等级起点及目标高度 | 9.79 | 67.63 | 按内容计算 | 12.64 |

弹匣与备弹采用共同的右锚点，约 `X=299`；原稿两个数字的右边缘相差约 1.21 个设计单位，折算后约 0.66 个参考布局单位，不需要在游戏中保留。左侧武器区约占卡片宽度的 65.5%，目前的 `224/320=70%` 应相应调整；现有字体需要额外宽度时可微调分区和留白。

### 暂用现有字体的文字处理

保留 `formatAmmo()` 和 `upgradeRoman()`。先确定数字可见高度，再用现有字体排版；不要把弹匣和备弹各自塞进 `87×37` 与 `40×14` 的框后独立求缩放，这会因字形宽度不同而改变 `8:3` 的关系。

数字组以备弹缩放 `s` 为公共基准：

```text
reserveScale = s
currentScale = s × 8 / 3

共同缩放后：
reserveScaleFinal = reserveScale × layoutScale × fitFactor
currentScaleFinal = currentScale × layoutScale × fitFactor
```

同一字体的数字用同一个可见字高基准校准 `s`，初始目标为备弹可见高度约 13.76、弹匣约 36.70。`font.lineHeight` 包含行间留白，只适合先做近似估计，不能作为实测可见高度。升级字形 `I/V/X` 与数字未必等高，另行校准到备弹可见高度的约 0.92 倍；常规情况下随数字组一起缩放。

- 常规三位弹匣和四位备弹使用稳定字号，`fitFactor=1` 为目标；为每一档位数预留足够宽度，避免因 `111` / `888` 等具体内容不同而每帧改变字号。
- 弹匣与备弹保持共同的右锚点，整串宽度由当前字体测量决定；优先利用可用留白、微调分区或卡片宽度，保住数字高度和层级。
- 如果空间仍不足，计算共同的 `fitFactor=min(1, 弹匣可用宽度/弹匣所需宽度, 备弹可用宽度/备弹所需宽度)`，两组数字一起缩小。所需宽度按该位数的保守上限估算，跨位数档才重新适配，不因每次射击更换字形而跳动。
- 四位以上弹匣、五位以上备弹同样先利用各自允许区域，再联动缩小；不能截断数据、覆盖图标或分别缩到失去 `8:3` 比例。极小屏幕下若不可读，使用第 6 节回退策略。
- 模式图标的位置和大小不随弹药字符串变化；等级零级隐藏，异常长罗马数字可单独缩小作为溢出处理，不反向拖小弹药数字组。
- 保留低弹量变红，其余数字保持白色 80% 不透明度。阴影暂沿用现有行为，测量字高时排除阴影，实机确认是否影响干净边缘。

验收以实际数字可见高度接近 `8:3` 为准，允许像素取整带来的小误差。缩小窗口时整体变小可以接受，但不能出现备弹与弹匣趋近同样大，或备弹被独立压缩到难以辨认。

### 稀有度和贴图

建议在 addon 内增加职责清晰的横向渐变绘制方法，例如 `drawHorizontalRarityGradient(...)`。四个顶点的左侧使用 alpha 41，右侧使用 alpha 0，同一 X 坐标上下颜色一致；通过实际顶点颜色分配确定方向。

稀有度配色以项目 `ZombiesRarityDisplay` 为准，SVG 原稿的 `#A200FF` 不再作为目标。优化稿已经改为史诗紫 `#A855F7`，后续游戏卡片直接复用项目颜色映射，避免另建一套卡片专属配色：

| 稀有度 | 项目颜色 |
| --- | --- |
| 普通 `common` | `#22C55E` |
| 稀有 `rare` | `#3B82F6` |
| 史诗 `epic` | `#A855F7` |
| 传奇 `legendary` | `#FF9800` |

各稀有度使用相同的渐隐规则；颜色随项目映射，不改变浅灰竖条与白色数字。

渐变 RGB 保持对应稀有度颜色，只衰减 alpha。原 SVG 末端 stop 未显式写颜色，通常按黑色参与插值；这里选择固定 RGB 渐隐是便于多稀有度统一的设计选择，不声称色彩插值逐像素一致。

枪图继续来自当前武器的 TaCZ HUD 资源，不能把参考图中的 HK416 静态图片作为所有枪械的显示内容。模式图标也继续复用现有 TaCZ 资源；取消统一的 0.8 乘色，并将图片框放大到参考比例。绘制后恢复 shader 颜色与相关渲染状态，避免影响其他 HUD。

保留枪图缺失时的物品图标回退，放在同一个枪图框内等比居中。当前 API 只返回资源位置，现有实现假设贴图画布为 `384×128`；首版可延续，但非标准枪包需要实机验证，不能为适配而直接裁掉透明边缘或拉伸武器。

## 6. 与布局一起处理的边界

### 自定义卡片隐藏时，保留可用的 TaCZ 信息

当前 `shouldReplaceTaczGunHud()` 仅检查模式、玩家和武器数据，不检查屏幕尺寸。`renderHeldWeaponPanel()` 则会因宽度小于 244 GUI 单位、缩放异常或高度不足直接返回。这会出现“自定义卡片没画出来，但 TaCZ 枪械 HUD 已被取消”的路径。

建议抽出共享的布局计算 / 可绘制判断，让渲染入口和 [ZombiesTaczHudSuppressor.java](../src/main/java/com/cdp/codpattern/event/client/zombies/ZombiesTaczHudSuppressor.java) 使用同一份规则。仅有合法数据还不够，必须确认当前尺寸下可显示。

当前结算阶段会在主渲染入口提前返回，隐藏判断也应明确这一状态的策略。如果结算界面要隐藏所有战斗 HUD，应显式表达为结算策略；其他情况下不应因为“替换”而丢失弹药信息。

### 小屏、GUI 缩放和其他 HUD

宽高都纳入缩放限制，避免仅限制宽度。先保持当前右下锚点，检查与左下玩家状态、中央交互提示及原版快捷栏的实际占用；参考图没有这些元素，不能仅凭 SVG 判断游戏内不会重叠。

极小窗口下若内容低于可读尺寸，则隐藏自定义卡片并保留 TaCZ 回退，不应强行把文字压成不可读像素。具体可读阈值应依据实际 GUI scale 截图设定，而不是直接把当前 244 GUI 单位判断复制过去。

## 7. 建议实现顺序与验证

1. 把卡片布局计算提取为统一结果，以 SVG 局部坐标为基准，按显示需要微调外框与留白，确认枪图不变形。
2. 修正横向渐变、alpha、浅灰竖条和图层顺序。
3. 按 `8:3` 联动设置弹匣和备弹大小，校准升级数字高度，再调整位置和固定模式图标，继续使用当前字体与实时数据。
4. 统一可绘制判断、TaCZ 隐藏条件及长数字适配。
5. 更新现有测试中绑定旧布局常量的断言，再进行客户端验收。

需要关注的测试文件：

- [ZombiesHudOverlayStaticContractCompatTest.java](../src/test/java/com/cdp/codpattern/client/gui/overlay/ZombiesHudOverlayStaticContractCompatTest.java)：目前锁定 `320×90`、左区 224、字号 `2.25/0.86` 以及 `fillGradient` 调用。实施新布局时需同步更新，不能为保留旧断言而保留错误渐变。
- [ZombiesWeaponPanelFormattingCompatTest.java](../src/test/java/com/cdp/codpattern/client/gui/overlay/ZombiesWeaponPanelFormattingCompatTest.java)：继续保留补零、不截断、零级隐藏和罗马数字逻辑。

针对提取后的布局逻辑，可验证长数字不越界、数字联动缩放后仍保持 `8:3`、常规位数内字号稳定、图标不随弹药跳动、小屏渲染与 TaCZ 抑制结果一致。不应把卡片宽高比完全等于 `586/153` 写成必须通过的断言。静态字符串检查不能代替这些行为检查，也不能代替渐变效果截图。

实机验收建议：

| 场景 | 通过标准 |
| --- | --- |
| 普通步枪，弹匣 30、备弹 120、升级 2 | 显示 `030` / `0120` / `II`；弹匣可见高度约为备弹 2.67 倍，升级略小于备弹；构图接近参考，枪图和数字不相交 |
| 相同数据，不同稀有度 | 仅淡色渐变换色，左条始终浅灰；不会出现大块实色遮挡 |
| 自动 / 半自动 / 连发切换 | 图标变化且位置不动，图标与备弹下行关系稳定 |
| 从 100 变为 99、从 10 变为 9 | 补零后的数字保持原字号和右锚点，不带动模式图标 |
| 四位弹匣、五位备弹、较长罗马数字 | 不截断数据、不越出区域、不覆盖相邻元素；弹匣和备弹联动缩放，仍保持大小层级 |
| 缺少 HUD 贴图、未升级、未知或缺失稀有度 | 分别按既有图标回退、零级隐藏、未知色 / 数据校验路径处理，不引入静态假数据 |
| 空手、非枪、切换房间或模式 | 不残留卡片，不误隐藏其他模式的 TaCZ HUD |
| 低弹量和空弹匣 | 延续现有红色提示与实时数字 |
| GUI scale 1/2/3/4、常见宽屏与小窗口 | 卡片比例允许微调，数字高度比保持接近 `8:3`，枪图和图标不变形；空间不足时 TaCZ 回退仍可用 |
| 明亮天空、暗处、复杂地面 | 无全屏黑底，淡色渐变不遮挡视野，数字仍可识别 |

本次交付核对原稿备份一致性、优化 SVG 渲染和数字比例、文档链接及代码定位；编译、行为测试及上述游戏内验收属于后续实际修改 HUD 时的验证工作。

## 8. 已完成的 SVG 小幅优化

本次只调整参考素材和文档。桌面源文件未改动，`zom-original.svg` 保存旧版；`zom.svg` 是当前建议使用的优化版。

| 项目 | 原稿 | 优化稿 | 原因 |

渐变与左侧竖条下沿从全画布 Y=`460` 延伸至 `463`，其余背景画布不变。枪图、弹匣、备弹、等级和模式图标均保留原有尺寸；备弹仅平移，所有数字的路径内容未重绘。

数字高度仍为 `67.2 / 25.2 / 23.148`，因此弹匣与备弹保持精确的 `8:3`，等级约为备弹的 0.919 倍。卡片加高后，弹匣 / 备弹可见高度约占卡片高度的 `43.1% / 16.2%`，仍然保持原有主次关系。

## 9. 游戏代码落地：紧凑卡片

根据“不必严格按像素、避免卡片过大”的补充要求，游戏内采用参考宽 240 的紧凑尺寸，再增加 2.5% 宽度容纳现有字体，最终为约 `246×63.89` 个参考布局单位。SVG 保持设计稿尺寸，不需要为了游戏显示大小重写素材。

- 默认参考宽从旧实现的 320 降至 246，减少约 23%；最大占屏幕宽度 30%、高度 20%，还会受窗口可用空间限制。
- 继续使用 `referenceScale()`，窗口大小相同时，GUI scale 变化不会放大卡片的物理尺寸。右下边距仍为 12 GUI 单位。
- 弹匣 / 备弹按 `8:3` 联动缩放，常规三位 / 四位数字保持稳定字号；按位数预留宽度，避免弹药变化导致字号抖动。长数字会一起缩小，极端不可读时恢复 TaCZ 回退。
- 暂用默认位图字体的可见字高估计 `lineHeight - 2`，不新增字体。大型数字取消阴影；自定义字体资源包的可见边界仍需实机校准。
- 枪图、模式图标等比显示；模式图标固定在下行左侧，备弹围绕该行中心对齐。升级数字维持略小于备弹的层级。
- 横向渐变由左右顶点 alpha 实现，左端 41、右端 0，颜色直接使用项目稀有度映射；浅灰竖条独立绘制。
- 卡片渲染与 TaCZ 抑制共用布局计算，空间不足或处于不绘制卡片的结算阶段时不以“替换卡片”为由隐藏 TaCZ。

核心改动位于 [ZombiesHudOverlay.java](../src/main/java/com/cdp/codpattern/client/gui/overlay/zombies/ZombiesHudOverlay.java) 与新增的 [ZombiesWeaponPanelLayout.java](../src/main/java/com/cdp/codpattern/client/gui/overlay/zombies/ZombiesWeaponPanelLayout.java)。原稿备份及优化 SVG 均保留。

新增定向验证任务 `gradlew.bat runZombiesWeaponHudCompat --offline`，覆盖布局、数字格式化和 HUD 接入的静态约束。布局检查包括 800–3840 宽屏幕、GUI scale 1–4、三至十位弹药、宽字体度量、数字行不相交、极小窗口回退。检查通过不等于游戏内观感验收；亮暗场景、特殊枪包和资源包字体仍需进游戏观察。
